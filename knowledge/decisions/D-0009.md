# D-0009: No structure search while the base values sample the price lists

Accepted 2026-10-06, on Rusty's go for the fix; built as 0.9.1 (0.9.0 whole, plus this). Amends
D-0006's base values, whose sampling skipped vanilla's treasure maps by name.

## What was seen

On the box, at pack 1.73.0's start: `Serfdom: base values for 501 items (383 from the price lists),
worked out in 2543 ms` on the server thread at `ServerStartedEvent`, then "Can't keep up" 3698 ms
behind just after `Done`. After a `/reload` the table goes stale and is rebuilt inside the first tick
that asks for a price, in play.

## What it was

Measured on a NeoForge 21.1.248 server on the desktop, with the box's 99 mod jars (every sha1
matched), its config, and a new world, the build timed part by part and listing class by class:

| Part | Time |
|---|---|
| The whole build | 10347 ms |
| Sampling, 31 professions, 502 listings x 3 seeds | 10335 ms |
| of which Backport 1.0.9's `ExplorerMapForEmeralds` (the cartographer's), 9 calls | **10183 ms** |
| the other 501 listings together | about 150 ms |
| Food, and `Values.table` | 11 ms |

The sampling skipped `VillagerTrades.TreasureMapForEmeralds` by class, since drawing a map searches
the world. Backport's explorer maps are its own class, and its `getOffer` (disassembled) does what
vanilla's does: `ServerLevel.findNearestMapStructure(tag, trader's position, 100, true)`, then
`MapItem.create` (a new map id and a saved map), `renderBiomePreviewMap`, and an offer of emeralds and a
compass. An offer with a second cost is never a simple one (`Values.seen`), so all that work gave no
price.

It also wrote to the world. The local run left `map_0.dat` to `map_8.dat` in a world nobody had
joined. On the box, maps 226 to 234 (nine ids in a row, their sizes the local nine's) were saved at the
first autosave after the 1.73.0 start, and none since (`idcounts.dat` unchanged from 02:27). They are
left in place: nobody was ever given one, and they are a few KB each. A search with skip-known set
marks the structure it finds as referenced, and a structure takes one reference
(`StructureStart.getMaxReferences` is 1), so those nine searches took the structures nearest 0, 0 out
of every cartographer's future maps. Read in the sources, not checked in the box's region files.

## Decision

While the price lists are sampled, a map's structure search finds nothing:
`mixin/ServerLevelMixin` asks `Prices.refusesSearch()` at the head of
`ServerLevel.findNearestMapStructure`, which is true only on the thread doing the sampling and only
while it does. A map listing then gives no offer before it searches or draws anything. The skip of
vanilla's class by name goes: the guard covers it, and so the GameTest server's own cartographer
exercises it. The log line counts the refusals (`... K map searches refused`).

With the box's mods, the build takes 245 ms (was 10347 on the same machine), values the same 501
items (383 from the price lists), refuses 42 searches (14 map listings), and saves no map.

## Rejected

- **A skip list naming Backport's class:** the next mod's map listing gets past it, exactly as
  Backport's got past vanilla's name.
- **Caching the table on disk, keyed by the mod list and data packs:** nearly every restart of the box
  is a pack release, which changes the key, so the start after each release would still stall; and it
  keeps the search and the maps.
- **Building a profession a tick:** spreads the 2.5 s but keeps the searches and the maps, and leaves
  the table missing values for its first ticks.

## Limits

- A listing that searches by another route (the chunk generator directly, its own scan) or is slow for
  another reason is not caught. The log line's time shows it.
- The GameTest world makes no structures (`GameTestServer`'s `WorldOptions(0, false, false)`), so a
  search there finds nothing with or without the guard: the GameTest counts the refusals and checks no
  map id is taken; the time and the maps were measured on the box's mods, before and after.
